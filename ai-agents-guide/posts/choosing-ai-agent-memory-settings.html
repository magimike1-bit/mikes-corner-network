Choosing AI agent memory settings: what to keep, summarize, and delete

Basics · 8 min read

Your agent remembers your old address, your previous employer's name, and a project that ended months ago, and it keeps offering all three back to you. Which of them should it keep word for word, which should survive only as a summary, and which should be gone entirely?

That is the real memory question. The settings screens make it look like one toggle, on or off. Underneath, every item in memory deserves one of three treatments, and the right treatment follows from two properties of the item: how long it stays true, and how much damage the exact wording does if it is wrong or exposed. Sort by those two properties and the settings choose themselves.

Three buckets for everything an agent remembers

BucketWhat belongs thereWhy this treatment
Keep, verbatimStable facts and standing preferences: your name as you write it, your timezone, output formats you always want, tools you use dailyThey change rarely, they are used constantly, and a paraphrase can quietly alter them
SummarizeLong running context whose detail has stopped mattering: finished project history, past decisions and their reasons, recurring topics from old chatsThe gist still helps the agent work with you; the word for word record mostly adds bulk and exposure
DeleteAnything time bound and past its date, anything sensitive that never needed keeping, duplicates of a fact that has since changed, one off details from a single taskStale facts get used as if current, and kept sensitive details are a standing risk with no offsetting use

Summarize is the bucket people use least, because products rarely label it that way, but the mechanism is common. Summary memory works by periodically compressing a conversation history into a running summary while the most recent exchanges stay in full. Know its price before you rely on it: the compression is lossy. Exact numbers, specific requests, and nuanced preferences can disappear in summarization. So the rule is strict. If losing the exact figure would change a decision, the item belongs in Keep, in full, or in your own files outside the agent. Summaries are for context, never for records.

The opposite failure also exists. Some memory keeps only the last stretch of a conversation and drops the rest, so a fact mentioned early simply vanishes. Neither extreme is a setting you chose; both are defaults you inherited. The buckets above are how you impose a choice on them.

What the two big products actually let you set

In ChatGPT, the controls live at Settings, then Personalization, then Memory, and depending on plan, region, and platform they can include separate switches for referencing saved memories and for referencing chat history, a memory summary, and a Manage view. Treat those as three different decisions, because they are. Saved memories are explicit items, stored separately from chat history. Reference chat history lets the product draw on past conversations more loosely, and that derived information can change as the product updates what it finds useful. The summary is a high level view of what may be used to personalize responses, and it does not necessarily include every detail the system can reference, so reviewing only the summary is reviewing a dashboard, not the store.

Claude sorts memory differently, as individual topics. Each topic sits in Settings, under Memory, where it can be read, edited, or deleted one at a time, and memory is on by default, including on free accounts. Two of its defaults are worth copying into your own rules whatever product you use. Sensitive topics are excluded by default: memory about health, race, ethnicity, religious beliefs, politics, and gender identity is not saved unless the user opts in, and some items, government ID numbers among them, are never saved at all, whatever the settings say.

Both products also offer the genuine no memory option for a single conversation. A temporary chat in ChatGPT does not create or update memories, even with personalization on. Claude's incognito chats, started from the ghost icon, stay out of memory the same way. One off sensitive work belongs there, not in a memory you then have to hunt down and delete.

The delete that is not a delete: chasing the copies

Here is the trap this whole guide exists to warn about. In ChatGPT, deleting the chat where you shared a detail does not automatically delete the saved memory that was created from that chat. The two live in separate stores. A complete removal means deleting the item in each place it survives: the saved memory itself, the memory summary entry, the original chat, any saved file in the product's library that contains it, and any connected app that holds the source. OpenAI also notes it may retain logs of deleted saved memories for up to 30 days for safety and debugging, so deleted means removed from use first and gone from every system later.

The engineering literature on agent memory makes the same point in stronger language. A delete control that removes one row but leaves a summary, a cache, a backup, or an export behind is not a complete deletion. Every derived copy of a memory, each summary it fed, each stored copy in another format, needs its own place in the deletion path. When you test a delete, test the result, not the button: ask the agent about the detail in a fresh conversation and see whether it resurfaces.

Two smaller controls follow from this. First, turning memory off is not deleting. In ChatGPT, switching Memory off does not delete past chats, and if it is switched on again later, new remembered information can be created from chats still in the history. Claude draws the same line with different words: pausing memory keeps the stored topics while stopping their use, while resetting deletes them permanently and cannot be undone. Know which of the three states, off, paused, or deleted, you actually put each product in.

Second, one time bound control is worth using precisely. Turning off Reference chat history in ChatGPT schedules the information remembered from past chats for deletion from OpenAI's systems within 30 days, while the chats themselves remain in your history and your saved memories stay untouched. It is the surgical option: history derived memory goes, explicit saved memories stay.

The monthly memory review, step by step

Memory drifts because it accumulates quietly. A short review on a fixed cadence keeps the three buckets honest:

  1. Open the full memory list, not just the summary. In ChatGPT that is Settings, Personalization, Memory, then Manage; in Claude, Settings, Memory, Topics. Ask the agent what it remembers about you as well, and compare the two views.
  2. Correct before you delete. Any fact that has changed gets edited or replaced in place. The maintenance rule for agent memory is explicit overwrite: an updated fact replaces the old one, it does not sit beside it, because two versions of your budget or your address guarantee the wrong one gets used eventually.
  3. Move finished context to the summary bucket. Projects that ended, decisions whose detail no longer matters: keep the outcome and the reason, let the blow by blow go.
  4. Delete the expired and the never needed. Time bound facts past their date, one task details, and anything sensitive that arrived without a purpose. Engineering guidance on memory retention is blunt here: do not store a candidate memory until a concrete future use justifies keeping it, and do not let something the model inferred about you, such as a health condition, harden into a durable fact without a purpose you chose.
  5. Chase the copies of anything sensitive you deleted. Check the source chat, saved files, and connected sources, using the list in the section above.
  6. Verify in a fresh conversation. Ask about one corrected fact and one deleted fact. The correction should appear; the deletion should not.

What success looks like: every item in the list is current, each changed fact exists exactly once, nothing time bound survives its date, and a fresh conversation confirms both halves, corrections live, deletions gone. Fifteen minutes is a generous budget once the first pass is done.

Settings to choose today, by how you use the agent

For everyday personal use, keep saved memories on, keep the list short and explicit, and run the monthly review; that combination is where memory earns its keep, in preferences and standing facts you would otherwise retype weekly. For client or confidential work, narrow the scope: use the product's project level memory where it exists, keep sensitive topics excluded, and route one off confidential sessions through temporary or incognito chats so nothing is written down in the first place. For shared devices or shared accounts, turn memory off entirely; a memory list written by two people is wrong for both of them. And whatever you choose, set retention by purpose, the principle the engineering guidance insists on: working state lasts as long as the task, preferences last while they are visible and correctable, and nothing lasts forever by default.
