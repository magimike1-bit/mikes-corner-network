What your AI chatbot remembers: review, correct, or delete it

Settings & privacy · Published 2026-11-01 · Last updated 2026-11-01

Start with the myth, because it points the wrong way twice. The first version says the chatbot remembers everything you have ever typed, forever. The second says it remembers nothing at all, so there is nothing to manage. Neither survives the documentation.

The model itself remembers nothing. Large language models are stateless, each request runs without built-in recollection of the one before, and what feels like memory is a separate system sitting around the model, which retrieves details and feeds them back in as context. That distinction is the whole guide. A separate system can be opened, read, corrected and emptied. A mysterious one cannot.

Three different things get called memory

Saved memories are the explicit layer: details you ask the chatbot to remember, or that it saves as useful context. In ChatGPT, OpenAI is explicit that saved memories are stored separately from chat history, a point with a sharp consequence, covered below.

Chat-history reference is the looser layer. With it on, ChatGPT can use relevant information from past conversations to personalise future responses, and what it derives can change as it updates what seems most useful. Gemini has the equivalent idea under its own naming, and Google notes Gemini can learn from past chats to understand more about the user.

Standing instructions are the layer you wrote yourself. OpenAI draws the line plainly: memory is different from custom instructions, which are direct guidance you provide about what the chatbot should know and how it should respond. Instructions are not memories the system gathered; they are orders you gave.

Two screens are in circulation for ChatGPT, which confuses beginners reading older guides. Depending on the account, the controls may appear as a single memory control with a memory summary, a high-level written view of what the system may use, or as toggles for Reference saved memories and Reference chat history with a list of saved items. OpenAI warns that if a setting described in its help is not visible, it may not be available for that account yet. An absent toggle is a rollout fact, not a mistake on your part.

Read the table for the pattern, not just the paths. Both systems separate what was gathered from what you ordered, both give you a summary view rather than a complete ledger, and both make availability depend on account type and region. Any third chatbot you try will organise the same three ideas under different names, find its summary view first.

The review, correct, delete procedure

Run this on ChatGPT first, where the controls are best documented, then repeat the pattern in any other chatbot you use.

  1. Open Settings → Personalization → Memory and read the memory summary before changing anything. Surprise is information: a detail you never knowingly shared arrived via chat-history reference.
  2. Correct what is wrong rather than deleting everything. Enter the correction in the summary’s text field, or highlight the wrong text and provide the correction. Do the same for any saved memory that is out of date.
  3. For a detail that should simply stop surfacing, use Don’t mention this again where it is offered, and understand its limit: it reduces future references but does not delete the original source.
  4. To remove remembered information properly, delete it at every layer it lives in: the saved memory or summary entry, the chat where you first shared it, any saved file in Library or Space that repeats it, and disconnect a connected app that holds it if you no longer want the chatbot to reach it.
  5. If the decision is “no memory at all,” use Delete and turn off memory from the summary’s more-options menu. It deletes the remembered information shown and turns Memory off. It does not delete your past chats, that is a separate job, in your chat history.
  6. Know the clock on chat-history reference: turning it off schedules the information remembered from past chats for deletion from OpenAI’s systems within 30 days, while the original chats remain until you delete them. Turning it off does not delete your saved memories; the layers really are separate switches.

What success looks like: the summary contains nothing you would be surprised to read aloud, every wrong detail carries its correction, and you can name which layers you cleared, because you cleared them one by one, on purpose.

Keep it on, turn it off, or go one-off

  • Keep memory on when the same preferences recur, answer format, ongoing projects, the context you otherwise retype weekly. That repetition is exactly what the feature exists to remove.
  • Turn it off when the account is shared, the work is sensitive, or the summary keeps collecting details you would not choose to store. Turning Memory off does not delete past chats, and turning it back on later can create new remembered information from chats still in your history, so pair the switch with the delete procedure above.
  • Use a one-off chat for a single sensitive question inside an otherwise useful account. In ChatGPT, choose the temporary chat’s personalisation setting before the conversation starts, including Unpersonalized if you do not want it to use existing memories, because that choice cannot be changed afterwards. Temporary chats do not create or update memories; saving one converts it into a regular chat, with regular rules.

What memory cannot do for you

Memory does not retain every detail from every conversation, and the summary is not a complete record. OpenAI says it may omit details, and that the system decides which available information is relevant to a given response. So never treat the chatbot as the archive of record for anything that matters. The contract, the booking, the medical note: those live in the original document, and memory is a convenience layer that points back toward them, sometimes inaccurately.

One more boundary, stated by OpenAI itself: turning Memory or personalisation off does not disable limited safety and security uses of context in rare, high-risk situations. Those uses are separate from personalisation controls. Knowing that line exists is part of managing the feature honestly, control what the controls actually control, and let the monthly five-minute review above handle the rest.
