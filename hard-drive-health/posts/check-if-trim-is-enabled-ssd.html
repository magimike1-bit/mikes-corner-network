How to Check If TRIM Is Enabled on Your SSD: Windows, Mac, and Linux, Layer by Layer

Drive monitoring · Published 2026-11-19 · Last updated 2026-11-19

Short answer: run the check for your system below, and do not stop at the first reassuring result. TRIM is a chain of three layers. The operating system must be set to send delete notifications, the drive and the connection it sits behind must accept them, and something must actually run the cleanup on a schedule. A pass at layer one with a failure at layer two looks exactly like a healthy drive from the settings screen, and it is the most common reason an SSD slowly loses write speed while every checker reports that TRIM is on.

What TRIM does, in one paragraph

When a file is deleted, the operating system normally just marks the space as free in its own records. The SSD still holds the old data and, without being told otherwise, treats those blocks as occupied. TRIM is the message that closes the gap. Kingston’s technical brief puts it plainly: the TRIM command lets the operating system and the SSD communicate where the deleted data sits and mark it for deletion, so when a file is deleted the drive learns that the address can be cleaned when it finds a convenient time. The drive’s own garbage collection, programmed in its controller firmware, does the actual recycling. TRIM supplies the information; it does not do the erasing itself.

The table is the whole method. Work down the rows for your platform, and treat the first row that fails as the problem to fix. Fixing a higher layer never repairs a lower one.

Layer 1 on Windows: read both lines of the fsutil output

Microsoft’s documentation for fsutil defines the setting precisely. The parameter is called disabledeletenotify, and it disables (1) or enables (0) delete notifications, also known as trim or unmap, the feature that notifies the underlying storage device of clusters freed by a file delete operation. The double negative in the name trips up most readers: 0 is the good result, because the disabling flag is off.

The part most guides skip is that the query answers separately for each file system, and the defaults differ. On NTFS, trim is enabled by default unless an administrator disables it. On ReFS v1, trim is enabled by default. On ReFS v2, trim is disabled by default. So an output that reads “ReFS DisableDeleteNotify is not currently set” is not an error and not a zero: it means no override exists and the file system’s own default applies, which for ReFS v2 is off. Home PCs run NTFS on the system drive, so the NTFS line is the one that matters there. A ReFS volume, most often a Storage Spaces pool or a server volume, needs its own reading, and Microsoft documents the separate override for it: fsutil behavior set disabledeletenotify ReFS 0.

Two more facts from the same Microsoft page keep the setting in proportion. Changing it requires no restart and no service restart, and it takes effect when the next unmap command is issued. And Microsoft notes that some devices may experience performance degradation when the delete notification feature is turned on, which is the documented reason the off switch exists at all.

Layer 2: a setting cannot send a command the drive never receives

Microsoft states the limit directly: if your hard disk drive or SAN reports that it does not support trim, then it does not get trim notifications, whatever the fsutil value says. Kingston’s brief names the usual blockers. TRIM depends on communicating with the drive over the storage interface, and if SSDs sit in a RAID array, behind an HBA controller, or in a NAS or SAN configuration outside the host PC, the TRIM command will not reach the SSDs. The same logic applies to the indirect connections Apple’s trimforce documentation warns about: devices connected through multi-protocol enclosures may not be accessible in a manner that supports TRIM.

That is why layer 2 has its own evidence on each platform. On Windows, the Optimize Drives tool and the Optimize-Volume cmdlet classify the drive: Microsoft’s cmdlet reference lists an SSD with TRIM support and an SSD without TRIM support as different cases, and only the first gets a retrim. On Linux, lsblk --discard shows the drive’s own advertised discard limits, and non-zero DISC-GRAN and DISC-MAX values are the drive saying it accepts the command. On a Mac, the TRIM Support line in System Information is reported per drive, under its SATA or NVMExpress entry, so an internal drive and an external drive can honestly return different answers on the same machine.

Layer 3: enabled is not the same as scheduled

Windows adds a periodic pass on top of the live delete notifications: a retrim, which re-sends the hints for space that is already free. Microsoft’s Optimize-Volume reference describes the ReTrim operation as generating TRIM and Unmap hints for all currently unused sectors of the volume, notifying the underlying storage that the sectors are no longer needed and can be purged. For an SSD with TRIM support, that retrim is the cmdlet’s default operation. For an SSD without TRIM support, the default is no operation at all, which makes a manual retrim a useful layer test: run it, and the verbose output tells you whether Windows believes the drive accepts TRIM.

Linux splits the job differently. Instead of notifying on every delete, most distributions run TRIM as a batch. Oracle’s Linux documentation describes the mechanism: the fstrim systemd timer unit periodically trims unused blocks on a file system, the default timer is configured to run weekly, and the frequency can be changed with a systemd override that sets OnCalendar. The continuous alternative, the discard mount option, exists, but the scheduled fstrim is the configuration to verify first, because it is the one most systems actually use.

Check TRIM on Windows, step by step

  1. Open an administrator prompt. Right-click Start, choose Terminal (Admin) or Command Prompt (Admin).
  2. Query the setting. Run fsutil behavior query DisableDeleteNotify and read the line for the file system your SSD volume uses, usually NTFS.
  3. Interpret the value. 0 means delete notifications are enabled. 1 means an administrator or a tool disabled them. “Not currently set” means the file system default applies: on for NTFS, off for ReFS v2.
  4. If the NTFS value is 1, re-enable it. Run fsutil behavior set DisableDeleteNotify 0, then repeat step 2 to confirm. No restart is needed.
  5. Test layers 2 and 3 together. In PowerShell (Admin), run Optimize-Volume -DriveLetter C -ReTrim -Verbose, replacing C with your SSD’s letter. Microsoft’s example uses exactly this form to re-send Trim requests to a volume.
  6. Confirm scheduled optimization is on. Open Defragment and Optimize Drives, check that your SSD is listed as a solid state drive, and that scheduled optimization is enabled.

What success looks like: the fsutil query shows 0 for your file system, the retrim command completes with verbose output instead of reporting that no operation applies, and the drive appears as a solid state drive in Optimize Drives. All three together mean TRIM is set, accepted, and running. A 0 in step 2 with a retrim that does nothing points at layer 2: the connection or the drive, not the setting.

Check TRIM on a Mac, step by step

  1. Open System Information. Apple menu, About This Mac, then System Report (on older systems, hold Option and choose System Information).
  2. Find your drive. Under Hardware, open SATA/SATA Express for a SATA SSD or NVMExpress for an NVMe drive, and select the drive.
  3. Read the TRIM Support line. Yes means macOS sends TRIM to that drive. No on an Apple-supplied drive is unexpected; No on a third party drive is the case trimforce exists for.
  4. For a third party internal drive showing No, back up first, then enable. In Terminal, run sudo trimforce enable, read the warning in full, and confirm.
  5. Restart and recheck. Apple’s man page states the change requires a reboot to take effect. After the restart, repeat steps 1 to 3 and confirm the line now reads Yes.

What success looks like: TRIM Support reads Yes for the specific drive you checked. Keep Apple’s own caution attached to step 4: the trimforce man page says to use extreme caution when enabling TRIM, as some drives may not correctly handle the commands, and it limits the tool to third party drives attached to an AHCI controller. A drive in an external enclosure that still reports No after a reboot is showing you a layer 2 limit, not a failed command, and forcing it further is not supported by the tool’s own documentation.

Check TRIM on Linux, step by step

  1. Ask the drive whether it accepts discard. Run lsblk --discard and find your SSD. Non-zero DISC-GRAN and DISC-MAX values mean the device advertises TRIM support.
  2. Check the schedule. Run systemctl status fstrim.timer. You want the timer loaded and active.
  3. If the timer is inactive, enable it. Run sudo systemctl enable --now fstrim.timer, the exact enable command in Oracle’s Linux documentation, then repeat step 2.
  4. Run one pass by hand to prove the chain. Run sudo fstrim -av. It reports the amount trimmed on each mounted file system that supports the operation.
  5. Note the cadence. The default timer runs fstrim weekly. A system that is rarely powered on at the scheduled time can go much longer between real runs, which the manual pass in step 4 covers.

What success looks like: the drive advertises non-zero discard limits, the timer shows active, and the manual fstrim reports a trimmed amount rather than skipping every file system. If step 1 shows zeros, the drive or the adapter in front of it does not pass discard, and no timer setting will change that.

When a layer disagrees, fix that layer only

Three results cover almost every real case. Setting off, drive capable: change the setting, using fsutil on Windows or trimforce on a Mac, and recheck. Setting on, drive or connection silent: change the connection before changing anything else, moving an external SSD to a direct port or a different enclosure, and accept that some RAID and NAS arrangements will never pass the command, as Kingston documents. Setting on, drive capable, nothing scheduled: turn the schedule on, in Optimize Drives on Windows or with the fstrim timer on Linux, and run one manual pass so the drive starts from a clean state. TRIM is maintenance, not a health verdict: a drive can pass all three layers and still be wearing out, which is what the health percentage and the error counters on this site’s other guides are for.
