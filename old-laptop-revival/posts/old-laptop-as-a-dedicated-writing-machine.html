Turn an old laptop into a dedicated writing machine: three routes, compared

Repurposing · 8 min read

3 routes lead to the same desk: a laptop that opens onto a blank page and nothing else. They differ in how hard the lock is, what the laptop must already run, and how easily the machine becomes a normal computer again. This guide takes them in order of strictness. Windows Assigned Access, a separate writing account, and lightweight Linux, and gives each one its gate check before its setup, because the strictest route is also the one most likely to be unavailable on the laptop in your drawer.

Route one: Assigned Access, the single-app lock

The gate. Assigned Access is a Windows feature that configures a device as a kiosk: a single Universal Windows Platform (UWP) application, or Microsoft Edge, runs in full screen, the signed-in account can use nothing else, and if the app is closed it restarts automatically. Microsoft lists the editions that support Assigned Access as Pro and Enterprise / Enterprise LTSC. Windows Home is not among them. Two further requirements apply to the kiosk experience: User Account Control must be enabled, and you must sign in at the machine itself, because the kiosk experience is not supported over a remote desktop connection.

Check the edition first: Settings > System > About. A spare laptop running Windows Home ends this route before it starts, and no setting inside Home unlocks it.

The setup. On an edition that passes the gate:

  1. Install the writing app first, and note the app-type limit: the kiosk experience runs a UWP app or Edge. A classic desktop editor cannot be the single kiosk app through this route, writers who need one should read route two instead.
  2. Sign in as an administrator and open Settings > Accounts > Other users, then start the kiosk setup.
  3. Create or choose a local standard user account for writing, not your administrator account.
  4. Assign the writing app to that account and finish the wizard.
  5. Sign in as the writing account to test: the configuration takes effect the next time the targeted user signs in, and the app should launch full screen on its own.

The model for what this feels like is documented in a published kiosk writing setup built on an aging laptop: a dedicated local account launches one writing app at sign-in, with no desktop, no browser, and no notifications competing for attention. The app criteria in that setup are the right ones for any route in this guide: full-screen writing, local autosave, and export to plain text or Markdown, so drafts are never trapped inside one program.

What success looks like: signing in with the writing account lands directly in the writing app, closing the app restarts it rather than revealing a desktop, and your normal account still signs in as a full computer when you need it.

Route two: a writing account, on any Windows edition

The gate. None. A separate standard account needs no particular Windows edition, which is why this is the route most spare laptops will actually use. The lock is softer, the writer signs into an account that contains only writing tools, while the rest of the computer remains one sign-out away. Route one's source makes the honest version of this trade: if notifications and open tabs are the main issue, a focus-level fix may be enough; a full kiosk addresses a device that invites multitasking as a whole.

The setup.

  1. Create a new local standard account named for the job. Writing is a perfectly good name.
  2. Sign into it once and install one writing app. FocusWriter is a fitting default: a free, open-source word processor, released under the GPL licence, built around a full-screen workspace whose menus stay hidden until the mouse moves to the edge of the screen. It offers daily writing goals, spell-checking, live statistics, multiple open documents, and automatic session restore.
  3. Remove or sign out of everything else in this account: no mail, no chat clients, no browser profile signed into anything.
  4. Set the writing app to start at sign-in, so the account opens onto the page.
  5. Keep all files for the account in one drafts folder, the export step at the end of this guide depends on it.

What success looks like: the writing account's desktop holds one app and one folder, a writing session starts without closing or muting anything first, and nothing in the account asks for attention that is not the document.

Route three: lightweight Linux, tested before it is installed

The gate. A Linux route ignores the Windows edition entirely and suits a laptop whose Windows install is itself part of the clutter. The discipline is the test: a lightweight distribution can be tried from a live USB before anything is erased, and the writing app named in route two is a Linux program as readily as a Windows one. FocusWriter's project ships for both worlds, so the drafting environment can stay identical whichever side of this comparison a writer lands on.

The setup.

  1. Back up anything on the laptop that matters, even for a test, the install step later is the destructive one.
  2. Boot the distribution from USB and write a real session in it: keyboard, screen brightness, sleep and wake, and saving a file are the four things to verify on the actual hardware.
  3. Install only if the live session passes, then add the writing app and nothing else.
  4. Create the same single drafts folder discipline as route two.

What success looks like: the laptop boots straight to a quiet desktop, the writing app opens full screen, and a saved draft is exactly where the export step expects to find it.

Getting drafts off the machine

Every route fails the same way if this step is skipped: a calm machine whose words cannot leave it. Settle the workflow before the first session, not after the first chapter.

  1. Write in an app that exports to plain text or Markdown, so no draft depends on one program to be readable.
  2. Keep every draft in the single folder set up in your route.
  3. At the end of a session, copy the folder to a USB drive or your main machine, the published kiosk setup this guide draws on works exactly this way, transferring saved files to the main machine later for editing, formatting, or publishing.
  4. Open the transferred file on the main machine once, immediately. A transfer that has never been opened is a hope, not a backup.

What success looks like: today's draft, written on the locked-down laptop, is open and readable on your main machine within a minute of the session ending, with the writing phase and the editing phase still kept apart, which was the point of the machine.

Which route, decided

Check the Windows edition and let it speak first. Pro or Enterprise on the spare: route one, if the writing app fits the UWP-or-Edge limit. Home, or a desktop editor you will not give up: route two, today, at no cost beyond setup time. A Windows install too tired to tidy: route three, after the live-USB test passes. Purpose-built writing hardware exists, dedicated writerDeck devices, down to an open-source DIY kit listed at $129, but buying one to solve a problem a drawer laptop already solves is spending money to avoid a setup wizard.
